## Each batch

1. Create the next unused `batch-NNN` directory here. Read raw source JSON and the current catalogue versions in full. Preserve exact before/after variants in `changes.json`; preserve full-reading evidence for changed and unchanged tasks in `review.json`. Record each existing finding’s disposition, new findings, source questions, reasons and tradeoffs. Store all open uncertainty outside the poem. A fluent-reader/author check has not occurred unless separately evidenced.
2. Make defensible corrections directly in each target language. Keep legitimate existing wording when it works. Hold only affected ambiguities; continue independent corrections in that poem and the rest of the batch. Do not infer grandmother lineage, narrator gender, dialect meanings, mythological facts or damaged source words. Do not delete or normalise original source records. Source contamination may be recorded for later editorial reconciliation; it is not permission to change the original.
3. Use the batch-001 schemas. Each change needs `poem_id`, `target`, `source_sha256`, exact `before` and `after` full variants, `reason`, `full_source_target_read: true`, and `independent_review: false`. Preserve draft status, labels, bylines and translator credits. Each review needs source hash, before/after full-variant hashes, current reading evidence, status, reasons, open questions and finding dispositions. Full-variant fingerprints use SHA256 of JSON with ensure_ascii=False and sort_keys=True, matching the original audit. Source fingerprints use SHA256 UTF-8 source.text.
4. Apply with `python3 tools/apply_translation_revision.py batch-NNN`. It rejects stale before versions and backs up the catalogue before writing. If interrupted after a write, inspect `catalog-before.json`, current catalogue and the planned changes; never overwrite a snapshot or reapply blindly. Only set batch integration status after reconciling the exact state.
5. Preserve full raw contributor tails in the catalogue. If target lineation changes, provide a checked `reader_layout` with source hash, stanza hash (compact JSON, ensure_ascii=False), target verse_line_count, before_lines and inline_breaks. The last two fields are explicit; do not copy source offsets blindly. Current explicit layouts require inline_breaks `[]`; use actual target lines for intended breaks. Text edits with an existing layout must refresh its hash and recheck boundaries. Changes to text with legacy inline offsets require explicit reconciliation before integration. Literary coverage must be read; shape checks cannot establish fidelity.
6. Run `python3 tools/test_translation_layout.py`, refresh the original translation inventory with `python3 tools/translation_queue.py`, and refresh the revision queue. Build with Node 24: `PATH=/Users/ahimanikya/.nvm/versions/node/v24.15.0/bin:$PATH ASTRO_TELEMETRY_DISABLED=1 npm run build` in projects/site. Run `python3 tools/check_editions.py` and `python3 tools/check_translation_revisions.py`. Save actual results in the batch verification. Inspect a browser when a new layout/script case makes visual checking useful. Keep the release gate, noindex, reader services and consent unchanged.
7. Update the loop record, KBL-WORK-023, activity and coverage; regenerate registers/catalogue and check bundle. Synchronize the portable handoff and check storage. Concurrent unrelated work must be preserved; report an unrelated parity failure without overwriting its changes. No push or deployment.

Continue as far as practical during each run, saving each batch before another. On interruption retain exact state and leave the heartbeat active. At the end of all actionable tasks, verify the full collection, pause this heartbeat with automation_update, and report corrected/retained variants separately from unresolved source questions and missing targets. Do not call held work fixed or self-review independent approval.

Future translation lessons should be evidence-backed and contextual. Accumulate them in the KB for later skill refinement; do not turn a preferred phrase into a universal replacement rule. Report meaningful edition milestones, actionable failures, or final completion; remain quiet when nothing actionable changes.
