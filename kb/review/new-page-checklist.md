# Kabita Live new page checklist

Use with the [website rulebook](../reference/website-rulebook.md) for a new page, edition or shared-template change. Copy the fields into the task’s KB review record; do not tick this master template. For a small change, complete only affected checks and explain omissions. Existing approval remains valid within its scope.

## Before implementation

- [ ] Read current rulebook and relevant latest decisions; distinguish them from historical notes.
- [ ] Confirm the source/template/data files to change; preserve concurrent work.
- [ ] Select meaningful artwork and correct credit; preserve source and masters.
- [ ] Check required reading tools, consent and response behavior for this page family.

## Before calling the page ready

- [ ] Content, attribution, language and stanza boundaries are correct for the authorized change.
- [ ] Desktop and phone presentation checked; long content, theme, keyboard and enlarged text considered.
- [ ] Image dimensions and responsive candidates checked; key artwork loads promptly, below-fold images retain lazy loading, static previews and WOFF2 fonts preserve design.
- [ ] Links and affected reading/form actions work; decoration does not obscure the action.
- [ ] Exactly one intentional sharing image; title, description, alt and canonical URL checked in initial HTML.
- [ ] Absolute image URL uses the hosting base correctly; image is in the public export and uncropped.
- [ ] Portrait, illustration, edition-cover or fallback mapping verified for this page family.
- [ ] Relevant tests and public build pass; known baseline failures remain documented separately.
- [ ] Originals, unrelated page content, runtime services and consent preserved.
- [ ] Review evidence states self-review versus independent review and unresolved findings.
- [ ] KB records/indexes refreshed; portable handoff synchronized and storage checked.

## When publication is authorized

- [ ] Actual release scope matches authorization; current remote changes preserved.
- [ ] Manual public-only workflow succeeds; preview/content gates and DNS remain as authorized.
- [ ] Live HTML and sharing image fetched; applicable reader/service checks completed.
- [ ] Record actual platform preview testing separately from HTTP metadata checks.
- [ ] Save release/workflow references and final status. Do not label a local result as live.
